# 00. なぜ今 Dafny を学ぶのか

## 位置づけ

Microsoft Research の Rustan Leino が 2009 年に始めた **検証指向言語**。
コードに事前条件・事後条件・ループ不変条件を書くと、SMT ソルバ (Z3) が自動でその正しさを証明する。
現在は AWS が主要な開発元の一つで、認証・認可基盤 (Cedar) などで実運用されている。

## 差がつくポイント

- **「証明された正しさ」を最も低コストで体験できる**。仕様 (`requires` / `ensures`) を書くだけで、証明は自動。Lean のように tactic を書く必要がない。
- **検証済みコードを他言語に出力**。C# / Go / Python / JavaScript / Java に変換して既存システムに組み込める。
- **実務での採用実績**。AWS (Cedar, S3 の一部)、Microsoft (IronFleet) など。「検証しながら書く」スタイルが実務で通じる。
- 検証が通らないときに **不変条件をどう直すか** という思考は、他の言語でのテスト設計や API 設計に直結する。

## 向いている用途 / 向いていない用途

| 向いている | 向いていない |
|---|---|
| アルゴリズム、データ構造、プロトコルの正しさ保証 | UI、I/O 中心のアプリ |
| 「絶対に間違えられない」ライブラリ (暗号、認可、決済) | 大規模なエコシステムが必要な開発 |
| 形式検証の入門 | 実行性能が最優先の処理 |

## 他の言語との比較

Lean は「自分で証明を書く」、Dafny は「仕様を書けば自動証明」。Dafny の方が入口は低く、複雑な性質になると自動証明の限界に当たる。
Rust の型システムはメモリ安全性を保証するが、「この関数は正しい値を返す」までは保証しない。Dafny はそこまで踏み込む。
