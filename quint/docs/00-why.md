# 00. なぜ今 Quint を学ぶのか

## 位置づけ

Informal Systems (Cosmos の形式検証チーム) が開発する仕様記述言語。
TLA+ の考え方 (状態機械 + 時相論理) を、型付き・プログラマ向け構文で書けるようにしたもの。モデル検査器 Apalache のフロントエンドでもある。

## 差がつくポイント

- **「コードを書く前に設計を検証する」技術を、現実的な学習コストで身につけられる**。TLA+ は強力だが構文と数学記法の壁が高い。Quint はその壁を取り除く。
- **実行できる仕様**。`quint run` でランダムシミュレーション、`quint test` でテスト、`quint verify` で網羅的モデル検査。反例が具体的なトレースで出る。
- **分散システム・合意アルゴリズム・決済** など「バグると高くつく」領域で実際に使われている (Cosmos, Tendermint 系プロトコル)。
- **型推論とエディタ支援**。TLA+ にはなかった型検査が、仕様の書き間違いを早期に見つける。

## 向いている用途 / 向いていない用途

| 向いている | 向いていない |
|---|---|
| 分散プロトコル、状態機械、ワークフローの設計検証 | アプリケーションそのものの実装 (Quint は実装言語ではない) |
| 「この設計で不変条件が破れないか」を確認したい | 無限の状態空間を扱う問題 (有限に切り出す必要がある) |
| TLA+ を学びたいが挫折した | 出力・I/O を伴う処理 |

## 他の言語との比較

TLA+ と 1:1 に対応する概念を持ち、`quint` は TLA+ への変換もできる。
Alloy は構造の検査、Quint / TLA+ は振る舞い (時間変化) の検査が得意。
Dafny や Lean が「実装が仕様を満たす」を証明するのに対し、Quint は「仕様 (設計) そのものが正しいか」を検査する。
