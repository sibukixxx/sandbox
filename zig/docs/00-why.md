# 00. なぜ今 Zig を学ぶのか

## 位置づけ

Andrew Kelley が 2016 年に始めた、C の後継を狙うシステム言語。
「隠れた制御フローなし、隠れたメモリ割り当てなし、プリプロセッサなし、マクロなし」を掲げ、その代わりに **comptime** で必要な抽象化を実現する。

## 差がつくポイント

- **comptime**: コンパイル時に Zig のコードがそのまま走る。ジェネリクス、型に応じたコード生成、テーブル生成、型安全な printf がこれ一つで実現される。C++ のテンプレート、Rust のマクロ、両方の役割を「普通の Zig コード」でこなす。
- **アロケータの明示**: 標準ライブラリはヒープを使う関数すべてが `Allocator` を引数に取る。「どこで割り当てが起きるか」が常に見え、組込みや高性能コードで有利。
- **クロスコンパイルとビルドシステム**: `zig build` は Zig で書き、どのターゲットにもビルドできる。`zig cc` は C/C++ のクロスコンパイラとしても使える (Rust や Go のプロジェクトが C 依存のビルドに Zig を使う例が多い)。
- **エラー共用体**: `!T` と `try` で、例外なし・戻り値ベースのエラー処理が言語機能として軽く書ける。
- **実運用の実績**: Bun (JS ランタイム)、TigerBeetle (金融 DB)、Ghostty (端末) など。

## 向いている用途 / 向いていない用途

| 向いている | 向いていない |
|---|---|
| OS、組込み、ゲームエンジン、高性能ライブラリ | 1.0 前の破壊的変更を避けたい長期案件 |
| C ライブラリの置き換え・ラップ | GC 前提で手早く書きたいアプリ |
| クロスコンパイルが必要なツール | 大きな Web フレームワークが必要な開発 |

## 他の言語との比較

Rust は安全性を型 (所有権) で保証し、Zig は「見えるようにする」ことで人が管理する。Zig の方が学習コストは低いが、メモリ安全性はコンパイラが保証しない (デバッグアロケータとテストで検出する)。
C との違いは、comptime、エラー共用体、Optional、スライス (長さ付きポインタ)、明示的アロケータ。C のコードはほぼ 1:1 で移植でき、`@cImport` で C ヘッダを直接読める。
