# 00. なぜ今 OxCaml を学ぶのか

## 位置づけ

Jane Street が社内で使ってきた OCaml の拡張を 2025 年に公開したもの。
標準 OCaml の上位互換で、**モード** (値の寿命・所有・利用回数を型に付ける) と **unboxed 型** (ヒープを経由しない値) を追加している。

## 差がつくポイント

- **GC 言語の書き心地のまま、割り当てを制御できる**。`local_` でスタック割り当て、`unique_` で in-place 更新、`[@zero_alloc]` で「この関数は割り当てない」をコンパイラに検査させる。
- **Rust の所有権に似た安全性を、後付けで**。全てのコードに所有権を要求せず、性能が必要な箇所だけモードを付ける。「GC あり言語の次」の設計として最前線。
- **unboxed 型 (`float#`, `#(int * int)`)** で、数値計算やレコードのメモリレイアウトを C 並みに制御できる。
- **既存の OCaml 資産がそのまま動く**。OCaml を学ぶ理由にもなる。
- 金融 (Jane Street) という「低レイテンシ + 正しさ」が両方要る現場で 10 年以上使われてきた実績。

## 向いている用途 / 向いていない用途

| 向いている | 向いていない |
|---|---|
| 低レイテンシが必要なサーバ、取引システム | OCaml 未経験で手早く成果が欲しい場合 |
| 数値計算・データ処理のホットパス | Linux 以外 (macOS は限定的、Windows は未対応) |
| 「GC のスパイクをなくしたい」既存 OCaml コード | 安定した言語仕様が必要な案件 (拡張は変化中) |

## 他の言語との比較

Rust は「全ての値に所有権」、OCaml は「全ての値を GC」。OxCaml はその中間で、既定は GC、必要な値だけモードで制御する。
Haskell の Linear Types や Koka の効果システムと同じく「型で資源を管理する」流れの一つで、実用規模での採用が最も進んでいる。
