# 00. なぜ今 Koka を学ぶのか

## 位置づけ

Microsoft Research の Daan Leijen が 2012 年から開発している研究言語。
「効果 (effect)」を型で追跡し、**代数的効果とハンドラ** を言語の第一級の機能として持つ。研究言語だが、C にコンパイルされ実用的な速度で動く。

## 差がつくポイント

- **効果型**: `fun f() : <exn, console> int` のように、関数が「何をしうるか」が型に現れる。純粋 (`total`)、発散しうる (`div`)、例外 (`exn`)、状態 (`st`)、I/O (`console`) が区別され、推論される。
- **代数的効果とハンドラ**: 例外、可変状態、ジェネレータ、async/await、バックトラック、依存性注入を「効果の宣言 + ハンドラ」という 1 つの仕組みで書く。他の言語ではそれぞれ別の機能として実装されているものが、Koka では同じもの。
- **次の言語設計を先取り**: OCaml 5 の effect handlers、Verse の効果指定子、Unison の abilities、Effekt、Flix はすべてこの考え方。Koka で学べば横展開できる。
- **Perceus**: 参照カウントと再利用最適化 (FBIP: functional but in-place) で、純粋関数型のコードが GC なしで in-place 更新される。
- **軽量**: 単一バイナリ、生成物は C。組込みへの応用研究もある。

## 向いている用途 / 向いていない用途

| 向いている | 向いていない |
|---|---|
| 効果システムそのものを学ぶ | 既存エコシステムが必要な業務アプリ |
| インタプリタ、DSL、制御フローが複雑なライブラリ | 大規模チーム開発 (ライブラリと資料が少ない) |
| 言語設計・PL 研究 | 安定性が最優先の案件 (研究言語) |

## 他の言語との比較

Haskell の monad は「効果を持つ計算」を型で表すが、複数の効果を組み合わせるには monad transformer が要る。Koka の効果は行多相 (`<exn|e>`) で自然に合成される。
Verse の `<decides>` / `<transacts>` は固定された効果の集合。Koka はユーザーが効果を定義できる。
